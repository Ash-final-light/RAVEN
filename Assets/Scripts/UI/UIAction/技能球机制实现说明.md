# 技能球机制实现说明

## 核心原则

技能球按键和技能连招不是同一个概念。

```text
SkillBall0 / SkillBall1 / SkillBall2 / SkillBall3
表示玩家按下第 0 / 1 / 2 / 3 个可见槽位。

SkillBallRed / SkillBallYellow / SkillBallBlue / SkillBallWhite
表示连招表中的颜色输入。
```

玩家按下数字键后，系统不会直接根据键位播放技能，而是先询问 `SkillBallManager`：

```text
这个可见槽位有没有球？
这个球是什么颜色？
这次应该单消还是三消？
```

技能动作由现有连招表决定：

```text
CurrentAction + 技能球颜色输入名 -> ComboInfoContainer -> nextAction
```

## 当前相关类

```text
BaseSkillDispatcher
战斗侧到 UI 的通信入口。负责通知 UI 消球、加球、替换角色图标、大招能量变化。

SkillBallManager
管理当前角色技能球队列、槽位输入、消除计算、Start 阶段消球命令。

SkillBallInputNames
把技能球颜色转换成连招表输入名，例如 Blue -> SkillBallBlue。

PlayerCharacterParameters
保存本帧输入脉冲和输入阶段的临时技能球数据。

PlayerStateMachine
接收有效技能球输入，用颜色输入名查询连招表，并尝试播放技能动作。

ActionPlayer.RuntimeContext
保存当前正在播放动作实例的技能球消耗数据，供伤害结算读取。

SelfCollideManager
碰撞结算时读取 ActionPlayer.RuntimeContext，根据消球数量选择 DamageHitConfigSO。
```

## 输入到播放技能动画

入口在 `PlayerCharacterBrain`。

```csharp
TryHandleSkillBallInput(InputConstants.SkillBall0, 0);
TryHandleSkillBallInput(InputConstants.SkillBall1, 1);
TryHandleSkillBallInput(InputConstants.SkillBall2, 2);
TryHandleSkillBallInput(InputConstants.SkillBall3, 3);
```

这里的 `InputConstants.SkillBall0` 是 Input System 的输入 Action 名，`0` 是可见槽位下标。

流程：

```text
1. 玩家按下 SkillBall0。
2. PlayerCharacterBrain 调用 TryHandleSkillBallInput("SkillBall0", 0)。
3. TryHandleSkillBallInput 检查输入是否在本帧触发。
4. 输入触发后，调用 Owner.SkillBallManager.TryPrepareUseBall(0)。
5. SkillBallManager 检查第 0 个可见槽位是否有球。
6. 如果没球，返回 false，本次输入不进入状态机。
7. 如果有球，读取该球颜色，例如 Blue。
8. 根据球颜色生成连招表输入名：SkillBallBlue。
9. 计算本次消除结果，例如单消或三消。
10. 写入 PlayerCharacterParameters 的临时字段。
11. PlayerCharacterBrain 设置：
    isSkillBallInFrame = true
    skillBallInputIndex = 0
```

`PlayerCharacterParameters` 中和技能球输入有关的字段：

```csharp
public bool isSkillBallInFrame;
public int skillBallInputIndex;
public SkillBallColor consumedSignalColor;
public string consumedSignalInputName;
public int consumedSignalCount;
public string consumedSkillActionName;
public int[] consumedSignalRuntimeIds;
```

这些字段的含义：

```text
isSkillBallInFrame
本帧是否有一次有效技能球输入。有效的意思是槽位上确实有球。

skillBallInputIndex
玩家按下的可见槽位下标。

consumedSignalColor
槽位上的技能球颜色。

consumedSignalInputName
颜色对应的连招输入名，例如 SkillBallBlue。

consumedSignalCount
本次预计消除的球数量。

consumedSkillActionName
状态机查连招表后得到的实际 ActionClip 名。

consumedSignalRuntimeIds
本次预计消除的球 RuntimeId，用于 UI 播放消除动画。
```

状态机处理：

```text
1. PlayerStateMachine.UpdateCurrentState 检查 isSkillBallInFrame。
2. 读取 consumedSignalInputName，例如 SkillBallBlue。
3. 调用 PlayerCharacterEvaluator.GetNextAction(CurrentAction, "SkillBallBlue")。
4. 连招表返回 nextAction。
5. 状态机把 nextAction 写回 consumedSkillActionName。
6. 调用 SkillBallManager.MarkPreparedConsumeForActionStart(nextAction)。
7. 调用 TryPlayAction(nextAction, false, CharacterStateType.Skill)。
8. 如果播放失败，调用 SkillBallManager.CancelPreparedConsume()。
```

注意：`MarkPreparedConsumeForActionStart` 必须在 `TryPlayAction` 之前调用。因为当前 `ActionPlayer.SetActionClipAndPlay` 会同步进入 Start 阶段。

## 播放技能动画到消球提交

技能球不会在输入阶段直接删除。真正删除发生在目标动作进入 Start 阶段时。

流程：

```text
1. PlayerStateMachine 已经标记待消球命令。
2. TryPlayAction 成功后，ActionPlayer.SetActionClipAndPlay 被调用。
3. ActionPlayer 进入 Start 阶段。
4. SkillBallManager 收到 ActionPlayer.OnStartStage。
5. SkillBallManager 检查当前动作名是否等于命令里的 actionName。
6. 匹配成功后调用 CommitPreparedConsume()。
```

`CommitPreparedConsume()` 做四件事：

```text
1. 把本次消球结果写入 ActionPlayer.RuntimeContext。
2. 从技能球队列中删除对应 RuntimeId 的球。
3. 通过 BaseSkillDispatcher 通知 UI 播放消除。
4. 清理 prepared command、pending command 和 PlayerCharacterParameters 中的临时消球字段。
```

这意味着命令数据只在 Start 阶段消费一次，消费后立刻释放。

## 播放技能动画到伤害计算

伤害计算不再读取 `PlayerCharacterParameters.consumedSignalCount`。

原因是角色动作可能被打断，`PlayerCharacterParameters` 是角色级数据，容易污染后续动作。

现在改为读取当前动作实例上下文：

```csharp
_character.ActionPlayer?.RuntimeContext?.ConsumedSignalCount
```

流程：

```text
1. 动作 Start 阶段，SkillBallManager 把消球结果写入 ActionPlayer.RuntimeContext。
2. ActionClip 播放过程中触发碰撞。
3. SelfCollideManager.TryResolveDamageConfig 读取 RuntimeContext.ConsumedSignalCount。
4. 如果 ConsumedSignalCount > 0，优先查当前碰撞片段的 signalBallDamageConfigs。
5. 找到对应数量的 DamageHitConfigSO，就使用该配置。
6. 没有找到则回退到默认 collideHitConfig。
7. ActionPlayer 切换动作、结束动作或被打断时，ClearData 会清空 RuntimeContext。
```

结果：

```text
普通攻击
ConsumedSignalCount = 0，使用默认 collideHitConfig。

技能球单消
ConsumedSignalCount = 1，优先使用 1 消 DamageHitConfigSO。

技能球三消
ConsumedSignalCount = 3，优先使用 3 消 DamageHitConfigSO。

动作被打断
ActionPlayer.ClearData 清空 RuntimeContext，不会污染下一个动作。
```

## PlayerCharacterParameters 更新流程

`PlayerCharacterParameters` 现在分两类数据。

第一类是本帧输入脉冲，每帧清理：

```csharp
isAttackInFrame
isSlideInFrame
isInteractInFrame
isSkillBallInFrame
skillBallInputIndex
```

它们在 `PlayerCharacterBrain.UpdateParameters()` 中清理。

第二类是技能球输入阶段的临时数据：

```csharp
consumedSignalColor
consumedSignalInputName
consumedSignalCount
consumedSkillActionName
consumedSignalRuntimeIds
```

这些字段的生命周期：

```text
TryPrepareUseBall
写入临时消球数据，供 PlayerStateMachine 查询连招表。

PlayerStateMachine
用 consumedSignalInputName 查 nextAction，并写入 consumedSkillActionName。

ActionPlayer Start 阶段
SkillBallManager 把消球结果写入 ActionPlayer.RuntimeContext。

CommitPreparedConsume 结束
清理 PlayerCharacterParameters 中的临时消球数据。
```

所以 `PlayerCharacterParameters` 只承担输入阶段的桥接作用；伤害阶段读取的是 `ActionPlayer.RuntimeContext`。

## 连招表配置要求

`ComboInfoContainer.inputTables.inputName` 中，技能球相关输入应该填写颜色输入名：

```text
SkillBallRed
SkillBallYellow
SkillBallBlue
SkillBallWhite
```

不要填写槽位按键名：

```text
SkillBall0
SkillBall1
SkillBall2
SkillBall3
```

槽位按键只负责定位 UI / 技能球池中的位置，真正进入连招表的是该槽位球的颜色。
