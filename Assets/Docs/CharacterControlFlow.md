# 角色控制流程说明

本文档把角色控制流程拆成两张图：

- 图 1：玩家输入到角色状态切换，回答“能不能进入某个状态”。
- 图 2：状态进入后到实际执行，回答“进入状态后实际发生什么”。

## 图 1：输入到状态切换

![输入到状态切换](CharacterControlFlow_InputToState.svg)

这张图关注玩家输入如何变成角色状态切换。

核心流程：

```text
输入设备
-> 输入读取
-> 输入意图
-> 控制权限判断
-> 资源/条件判断
-> 状态机决策
-> 切换到目标状态
```

关键点：

- 输入只是意图，不代表一定执行。
- 控制权限会拦截死亡、受击、硬直、UI/对话、暂停等状态。
- 条件判断会检查 MP、技能球、冷却、目标、取消窗口、Combo 条件等。
- 状态机负责最终决定是否切换到移动、攻击、闪避、技能、大招、受击、死亡等状态。

## 图 2：状态到实际执行

![状态到实际执行](CharacterControlFlow_StateToExecution.svg)

这张图关注角色进入状态后，动作如何真正产生位移、事件、碰撞、伤害和表现反馈。

核心流程：

```text
角色状态
-> ActionClip / 动画播放
-> 动作 Tick
-> 位移执行
-> 动作事件
-> 碰撞检测
-> 战斗结算
-> 表现反馈
-> 动作结束或被打断
```

关键点：

- 状态切换只是开始，真正的行为由 `ActionClip` 持续 Tick 驱动。
- 位移执行包含普通移动、攻击位移、闪避位移、技能位移、朝向修正、攻击辅助/吸附等。
- 动作事件负责开关无敌、霸体、不可破防、取消窗口，也可以发射子弹、生成特效、播放音效。
- 碰撞检测命中后进入 `SelfCollideManager`，再连接到伤害流程。
- 外部事件如受击、死亡、破防、时间缩放、Buff，可能影响或打断当前执行。

## 两张图的边界

```text
图 1：输入意图是否能切到目标状态。
图 2：目标状态开始后如何实际执行并产生结果。
```

角色控制主链路可以理解为：

```text
输入不等于执行
-> 状态机决定能不能做
-> ActionClip 决定怎么做
-> 战斗系统决定造成什么结果
```
